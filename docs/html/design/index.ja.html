Tasq のアーキテクチャと実行時境界

Tasq は、ユーザーが扱う issue state と orchestration runtime state を分離します。issue-tracker は UI、TUI、CLI、reconciliation の安定した API であり、orchestrator は run、runner event、workspace metadata、loopback inspection を所有します。

issue-tracker が issue data を所有 orchestrator が run data を所有 client は orchestrator に直接依存しない workspace と runner は runtime boundary Generated: 2026-06-15 HTML ビジュアルガイド

概要

設計の中心は、issue management、run orchestration、agent execution の責務を分けることです。これにより、人間と agent は同じ issue API を共有しながら、UI client を一時的な runner state に結合せずに済みます。

User-facing API web-ui、tui、tq は issue-tracker を主要な API 境界として使います。
Runtime state orchestrator は run、event、workspace、setup failure を自分の SQLite database に保存します。
Local-first data service state は TQ_HOME 配下の SQLite database と file に置かれます。
Agent boundary 将来の Codex app-server 連携は runner と workspace manager の責務境界に閉じます。

アーキテクチャ

focus button で責務の経路を絞り込めます。この図は依存方向と state ownership を示すためのもので、network topology そのものではありません。

構造

command entry point、issue domain、orchestration runtime package は分けて配置されています。この HTML は静的な参照資料であり、下記の source file が一次情報です。

Command entry points

  • cmd/issue-tracker - user-facing API service
  • cmd/orchestrator - run orchestration process
  • cmd/tq - issue-tracker API を使う CLI
  • cmd/tasq-tui - terminal UI client
  • cmd/web - Go web server と React frontend

Internal ownership packages

  • internal/issue
    • api, domain/entity, store
  • internal/orchestrator
    • coordinator, runner, runstore, workspace, workflow
  • internal/cli/tq - CLI command behavior

フロー

orchestration path は issue-tracker から read-through し、orchestrator runstore へ write-through します。orchestrator は issue status を直接 mutate しません。

Issue が actionable になる user または agent が issue-tracker API / tq で issue status を更新します。
Orchestrator が reconcile する candidate issue と workflow configuration を読みます。
Workspace を準備する issue ごとに sanitize された workspace を作り、metadata を保存します。
Runner が実行する 将来の Codex app-server work は runner event として進捗を報告します。
Inspection は local に閉じる run record と diagnostics は optional loopback API から参照します。

状態所有

issue-tracker Issue state

Issue state は user-facing な状態であり tracker database が所有します。orchestrator は read しますが直接 mutate しません。

backlog ready in_progress review done blocked failed

orchestrator Run state

Run state は operational history と diagnostics です。runner event と workspace metadata と一緒に orchestrator runstore に残ります。

queued running succeeded failed cancelled
State / artifact Owner Storage Mutation path
Issue title, body, priority, status, assignee issue-tracker SQLite issue database Issue API, tq, UI, TUI
Comments and attachment metadata issue-tracker SQLite + files under TQ_HOME Comment and attachment APIs
Run records, attempts, runner events orchestrator orchestrator SQLite runstore Coordinator and runner boundary
Workspace metadata and setup failures workspace orchestrator SQLite runstore Workspace manager

API Surface

現在の安定した user-facing API は issue-tracker です。orchestrator HTTP は loopback / runtime inspection 用であり、主要な client contract ではありません。

Issue-tracker endpoints

Area Representative endpoints
Health + summary GET /api/v1/health, GET /api/v1/summary
Projects GET/POST /api/v1/projects, workflow check and override APIs
Issues GET/POST /api/v1/issues, PATCH /api/v1/issues/{id}, POST /api/v1/issues/states
Comments + attachments POST /api/v1/issues/{issueId}/comments, attachment upload/content/delete APIs

Response and CLI contract

Contract Shape
Success JSON { "data": ..., "meta": {} }
Error JSON { "error": { "code": "...", "message": "..." }, "meta": {} }
CLI default terminal 向けの human-readable text
CLI tools agent / script 向けに --output json を使います。

運用

local development は Docker Compose の long-lived dev container と、tq による host-only services の 2 形態を想定しています。

Compose development make dev-up は OpenAPI UI、issue-tracker、orchestrator、web を dev container で起動します。
Host-only services tq service start は tracker、orchestrator、web を local ports 37651-37653 で起動します。
Migrations first migration がある場合は service 起動前に tq migrate または make run-migrate を実行します。
Verification Command What it protects
Go tests go test ./... backend domain、store、API handler、orchestration packages
Web build cd cmd/web/frontend && npm run build React production build と frontend integration
Web typecheck cd cmd/web/frontend && npm run typecheck TypeScript contracts と component usage

リスク / 未決事項

Tracker sync boundary external tracker sync は未決です。issue-tracker ownership と provider interface の切り分けが必要です。
Transcript storage 大きな Codex transcript は SQLite row ではなく filesystem artifact にした方がよい可能性があります。
Production exposure authentication、authorization、network exposure は現時点の MVP scope 外です。
