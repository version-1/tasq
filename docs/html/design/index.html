Tasq Architecture

Issue management and agent orchestration are separated into two SQLite-backed services. UI clients use the issue-tracker as the only user-facing API.

MVP slice: issue-tracker + orchestrator boundary

Service Dependency Map

web-ui

Next.js operational UI.

  • Calls issue-tracker only
  • Shows issues and latest runs

tui

Go terminal UI.

  • Calls issue-tracker only
  • Supports watch mode

issue-tracker

Source of truth for issue state and display aggregation.

  • SQLite: issues, work items, received events, run snapshots
  • Creates work items when issues become ready
  • Accepts idempotent orchestrator events
UI/TUI -> issue-trackersummary, issue CRUD, status updates
orchestrator -> issue-trackerclaim work item, push run event

orchestrator

Source of truth for run state and outbox delivery.

  • SQLite: runs, outbox events
  • Polls and claims work items
  • Pushes run events with retry

future agent/workspace

Codex app-server and isolated git workspaces.

  • JSON-RPC agent protocol
  • Parallel workspace execution

State Ownership

State Owner Notes
Issue title, body, priority, status issue-tracker User-facing source of truth.
Work item claim and lease issue-tracker Prevents duplicate execution across orchestrators.
Run records and attempts orchestrator Created after successful claim.
Outbox delivery orchestrator Run events are retried until accepted.
Displayed run snapshot issue-tracker Derived from accepted orchestrator events.
Rendered dashboard web-ui/tui No direct orchestrator calls.

Execution Sequence

1. Ready issue User moves an issue to ready. The issue-tracker creates a pending work item.
2. Claim lease Orchestrator polls the queue and claims one work item with claimed_by, claim_token, and lease_until.
3. Run record Orchestrator stores a run in its SQLite database and writes run events to the outbox.
4. Event push Outbox events are pushed to the issue-tracker. Duplicate event ids are accepted without double applying.
5. Summary Issue-tracker applies valid claim-token events, updates issue status, and serves summary to web-ui and tui.

Late events from expired claim tokens are recorded as received events but do not update issue state.
