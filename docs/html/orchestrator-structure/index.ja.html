Tasq Symphony Orchestrator Structure

ローカル Symphony orchestrator の構造を、composition root、パッケージ境界、 実行時の協調、runner プロトコル、永続化状態、運用上の注意点に分けて整理した HTML です。

概要

Composition rootcmd/orchestrator が SQLite store、issue tracker client、workflow config、Codex runner を組み立てます。
Coordinatorworker が polling、claim、workspace setup、run lifecycle、lease renewal、retry、reconciliation、cleanup、outbox flush を担当します。
Persistencerunstore が runs、runner events、workspace metadata、setup failures、outbox events を SQLite に保存します。
External APIstracker は issue-tracker HTTP API、runner.CodexRunner は codex app-server の JSON-RPC と接続します。
Workspace boundaryworkspace.Manager が issue key を sanitize し、root escape を防ぎ、必要に応じて source をコピーします。
Workflow contractWORKFLOW.md の front matter が poll interval、workspace path、concurrency、turn、retry、stall、Codex timeout を制御します。

アーキテクチャ

orchestrator は command bootstrapping、coordinator、adapter、domain model、外部境界に分かれています。

実行フロー

各 tick は未送信 outbox を先に flush し、その後 work item を claim して runner 実行と lease renewal を進めます。

sequenceDiagram
  autonumber
  participant Main as cmd/orchestrator
  participant Worker as worker
  participant Store as runstore
  participant Tracker as issue tracker
  participant WS as workspace.Manager
  participant Runner as runner.CodexRunner

  Main->>Store: Open(db) + migrate schema
  Main->>Worker: NewWithConfig(definition, CodexRunner)
  Worker->>Tracker: Issues()
  Worker->>WS: terminal issue workspace cleanup
  loop poll interval
    Worker->>Store: UnsentOutboxEvents(limit=20)
    Worker->>Tracker: SendRunEvent(event)
    Worker->>Store: MarkOutboxEventSent(id)
    Worker->>Tracker: ClaimWorkItem(orchestratorID, leaseSeconds)
    alt work item なし
      Worker-->>Worker: 次の tick まで待機
    else claim 成功
      Worker->>WS: CreateForIssue("issue-{id}")
      Worker->>Store: UpsertWorkspaceMetadata(...)
      Worker->>Store: CreateRun(status=queued)
      Worker->>Store: UpdateRunStatus(running)
      par runner execution
        Worker->>Runner: Run(ctx, Task)
        Runner-->>Store: RecordRunnerEvent via callback
      and lease loop
        Worker->>Tracker: Issue(id) for reconcile
        Worker->>Tracker: RenewWorkItemLease(...)
      end
      Worker->>Store: UpdateRunStatus(result.status, result.error)
      Worker->>Store: UnsentOutboxEvents(...)
      Worker->>Tracker: SendRunEvent(...)
      opt failed or cancelled
        Worker->>WS: RemoveForIssue(...)
        Worker->>Store: MarkWorkspaceCleanup(...)
      end
    end
  end

Runner プロトコル

flowchart TD
  A[Task validation: workspace, command, timeouts] --> B[Prompt template rendering]
  B --> C[Start bash -lc codex app-server]
  C --> D[JSON-RPC initialize]
  D --> E[initialized notification]
  E --> F[thread/start]
  F --> G[turn/start first prompt]
  G --> H{turn/completed?}
  H -- succeeded --> I{continuation enabled and turns remain?}
  I -- yes --> J[turn/start continuation guidance]
  J --> H
  I -- no --> K[Result succeeded]
  H -- failed/error --> L[Result failed with error text]
  C --> M[stderr scanner records runner event]
Task contractWorkItem、RunID、Workspace、prompt template、max turns、continuation flag、command、read/turn timeout、OnEvent を渡します。
Result contractStatus は run status に戻されます。Error は永続化され、outbox 経由で tracker に送られます。
Event contractrunner event は event type、message、payload JSON、run id、occurred_at を保存し、運用可視性を確保します。

状態と永続化

状態は worker のメモリ、SQLite、filesystem workspace、tracker 側 lease/status に分かれています。

stateDiagram-v2
  [*] --> queued: CreateRun
  queued --> running: UpdateRunStatus
  running --> succeeded: runner success
  running --> failed: runner failure / stalled / retries exhausted
  running --> cancelled: terminal or non-active issue reconcile
  failed --> [*]
  succeeded --> [*]
  cancelled --> [*]

リスク / 未確認点

Concurrency semanticsmaxConcurrent、running、claimed はありますが、現在の tick path は claim した item を inline で実行します。設定値どおりの並列 throughput を前提にする前に確認が必要です。
Process restart recoveryruns と outbox は永続化されますが、active な running/claimed メモリ状態を active run から replay して復元する形ではありません。
Prompt renderingtemplate substitution は issue id/title/description と attempt に絞られています。追加 field は contract 変更が必要です。
Runner observabilityrunner events と setup failures は保存されますが、運用 UI/API として見せる部分は別途 consumer 側に依存します。
Filesystem costsource tree copy は .git、.worktrees、node_modules を skip しますが、大きい repo ではまだコストが高くなり得ます。
External process contractCodexRunner は codex app-server の JSON-RPC shape に依存します。protocol drift には integration coverage が必要です。
