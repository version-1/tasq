概要

主な役割 Issue tracker から対象 issue を読み、issue ごとの workspace を作り、coding agent session を実行します。
Policy は repository 内 WORKFLOW.md が runtime settings と prompt template を持ちます。
Scheduler authority は 1 つ Orchestrator が dispatch、retry、live session metadata を所有します。
Agent 実行は分離 各 issue は sanitize 済み workspace path に割り当てられます。
Tracker writes は境界外 Symphony は scheduler / runner / tracker reader で、ticket 更新は通常 agent tooling 側の責務です。
Recovery は tracker/filesystem driven restart 後に retry timers や live worker state は復元せず、tracker と workspace から再開します。

実行フロー

tick は必ず active run の reconciliation から始まります。config が invalid な場合は新規 dispatch を止めますが、 可能な限り service と reconciliation は継続します。

01
Startup

logging、workflow watch、config validation、terminal workspace cleanup。

02
Poll Tick

reconciliation、dispatch preflight、active candidate fetch。

03
Eligibility

claimed/running、blocker、state、slot limit を確認。

04
Dispatch

in-memory claim、worker 作成、workspace 準備、prompt build。

05
Agent Turns

最初の prompt と continuation turns を同じ live thread で実行。

06
Exit / Retry

running entry を解除し、metrics 更新、continuation または backoff retry。

契約

Workflow contract

WORKFLOW.md は optional YAML front matter と strict prompt template を持ちます。

tracker:
  kind: linear
  api_key: $LINEAR_API_KEY
  project_slug: example
polling:
  interval_ms: 30000
workspace:
  root: ~/symphony_workspaces
Tracker contract

scheduler は candidate fetch、state refresh by id、terminal-state fetch for cleanup を必要とします。

fetch_candidate_issues()
fetch_issues_by_states(state_names)
fetch_issue_states_by_ids(issue_ids)
Agent runner contract

per-issue workspace で Codex app-server を起動し、prompt を render し、events を orchestrator に流します。

workspace -> prompt -> app-server session
first turn: rendered issue prompt
continuation: same thread + short guidance
Observability contract

structured logs は必須です。runtime snapshot、dashboard、JSON API は recommended / optional surface です。

issue_id=... issue_identifier=...
session_id=...
action=dispatch outcome=completed

安全性と Failure Handling

MUSTWorkspace cwd

coding agent は必ず cwd == workspace_path で起動します。

MUSTRoot containment

resolved workspace path は resolved workspace root の配下に留まる必要があります。

MUSTSanitized key

workspace names は [A-Za-z0-9._-] のみを許可し、他は _ に置換します。

SHOULDSecret handling

secret は env indirection で解決し、token value を log に出しません。

SHOULDHook safety

hook には timeout を設定し、log output は必要に応じて truncate します。

SHOULDHarness hardening

approval、sandbox、network、credential posture を deployment ごとに文書化します。

主要リスク: permissive deployment では repository data、tracker data、credentials、host filesystem が agent に露出し得ます。 spec は approval / sandbox posture を implementation-defined としているため、各実装が safety model を明記する必要があります。

Tasq 差分

Tasq は Symphony specification を方針として使いますが、tracker adapter boundary は local issue-tracker API に置き換えています。

Tasq は spec の Linear tracker client を直接実装していません。local issue-tracker API を tracker adapter boundary とし、 issue ownership と lease-backed work item claims を既存 service boundary に残します。
